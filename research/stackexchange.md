# Stack Exchange network mining — recurring "missing everyday/dev tool" pain points

Method: `curl --compressed` against `https://api.stackexchange.com/2.3` (no key), 25 requests total,
1s sleep between each. Endpoints used: `/questions?order=desc&sort=votes&tagged=...&pagesize=30`,
`/search/advanced?order=desc&sort=votes&q=...&pagesize=30`, `/tags?sort=popular&pagesize=40`.
Sites hit: stackoverflow, superuser, serverfault, unix, webapps, apple, android, academia, money.
All titles / view counts / answer counts / dates / URLs below are copied verbatim from API JSON
(stored in `/tmp/cora/se/*.json`). Titles were printed by my own reader capped at 95 chars, so any
title ending in `…` is truncated at the tail (marked UNVERIFIED for the missing tail only).

Quota observed: started at `quota_remaining=298`, ended at `274`. No `backoff` field returned on any
call. Two non-fatal anomalies, quoted in full at the bottom.

## Cross-cutting themes (what a missing tool would cover)
- **Reversibility**: rows 1, 4, 15 — the #1 traffic driver is "put it back", and no everyday tool offers a versioned undo journal for git/files/disk.
- **Local inspectors**: rows 2, 4, 7, 19 — "tell me what is holding/using/changing X right now, and let me stop it" is answered with 4 different OS-specific commands.
- **Format/normalization converters**: rows 9, 10, 11, 14 — PDF/JSON-CSV/encoding/HEIC-video all want one trusted local batch converter with sane defaults.
- **Batch file operations with preview**: rows 5, 8, 18 — rename/compare/touch/repair across a tree, ideally dry-run + undo.
- **Scheduled decay monitors**: rows 13, 16, 17 — things that silently grow (disk images, logs) or silently expire (certs, trials, subscriptions) with no unified watchlist.

## API errors / anomalies (verbatim)
1. Pre-flight probe `GET https://api.stackexchange.com/2.3/info/site/stackoverflow?filter=!nNPvSNdWme` → **HTTP 400** (body not captured; cause was my own invalid `filter=` value, not a quota/backoff condition).
2. The closed-questions call `GET /2.3/questions?order=desc&sort=activity&site=stackoverflow&tagged=closed&pagesize=30` returned **HTTP 200 with an empty result set**, because `closed` is not a tag:
   `{"items":[],"has_more":false,"quota_max":300,"quota_remaining":280}`
3. No `backoff` and no error payload were returned by any of the 25 mined calls; quota decremented monotonically 298 → 274.

## Not pursued / negative results
- `/search/advanced` matches loosely: `q=duplicate files` and `q=monitor folder for changes` returned many off-topic rows (SSH config, mouse deselecting), so those two result sets were used only where the title was genuinely on-topic.
- `/questions?tagged=closed` is not a valid way to sample closed questions (see above).
- academia / money / webapps evidence is materially lower-view (10k–40k) than stackoverflow/superuser (100k–16M); those rows are flagged in-table rather than dropped, since dispersion (many small asks) is itself a signal.
