## Discussions: reachable vs not (REST `GET /repos/{owner}/{repo}/discussions`)

- **Reachable (HTTP 200)**: `vitejs/vite` (e.g. discussion #1625 "define override rollup output intro", #1651), `vercel/next.js`, `excalidraw/excalidraw`, `cli/cli`, `zed-industries/zed` (zed#58974 was literally opened *from* discussion #49245, quoted in the issue body I fetched).
- **Not reachable (HTTP 410, body `{"message":"Discussions are disabled for this repo","documentation_url":…}`)**: `home-assistant/core`, `microsoft/vscode`.
- **Discussion search via REST is not supported**: `GET /search/issues?q=repo:vitejs/vite is:discussion` returned HTTP 422 `{"message":"Query must include 'is:issue' or 'is:pull-request'","documentation_url":"https://docs.github.com/rest/search/search#search-issues-and-pull-requests","status":"422"}`. GraphQL was not available, so **no cross-repo discussion ranking was possible — the discussion pain above is only sampled, not exhaustively ranked (UNVERIFIED coverage)**.

## API errors / anomalies seen (verbatim where applicable)

- `{"message": "Query must include 'is:issue' or 'is:pull-request'", "documentation_url": "https://docs.github.com/rest/search/search#search-issues-and-pull-requests", "status": "422"}` (search for `is:discussion`).
- HTTP 410 `Discussions are disabled for this repo` — `home-assistant/core`, `microsoft/vscode`.
- `{"message": "Moved Permanently", "url": "https://api.github.com/repositories/192925833/issues/5051", ...}` for `prisma/prisma#5051`; re-fetched with `curl -sL` — canonical URL is `https://github.com/prisma/orm/issues/5051`.
- `repo:git/git is:issue is:open` → HTTP 200 but `total_count: 0`: the git/git mirror has no issue tracker, so **git/git could not be reached for pain mining**.
- `repo:SYSTRAN/faster-whisper is:issue is:open` returned only `total_count: 5` with top open issue at R3 — anomalously low for that repo's size; possible rename/index quirk. **UNVERIFIED — treated as a weak source and dropped from the table.** Same for `repo:remotion-dev/remotion is:issue is:open` (`total_count: 169`, max reactions R2) and `repo:juliangarnier/anime` (max R19): trackers too quiet to prove recurrence.
- Local tooling error, not API: executing `/tmp/cora/comments.sh` directly gave `bash: line 1: /tmp/cora/comments.sh: Permission denied` (missing exec bit); re-run as `bash /tmp/cora/comments.sh`.
- No 403 rate-limit or secondary-limit responses occurred. Request budget: ~38 search requests + ~32 core requests ≈ 70 total — over the ~50 target, though well inside the 5000/hr core and 30/min search limits (all calls were spaced 1–3 s apart).

## Reading of the data (what a small static tool could actually absorb)

Highest signal-per-effort, purely from the rows above: error-text decoding (#3, #9), cron/timezone preview (#5, #6), date/UTC inspection (#10), semver-range explanation (#4), merge-conflict hunk resolver (#7, #8), JSON⇄YAML+config-merge preview (#13, #15), URL/trailing-slash canonicaliser (#14), CORS/preflight inspector (#1), encoding converter (#12), contrast checker (#11), cache/service-worker inspector (#2). All are client-side-only problems: the input is text the user already has, and no upstream maintainer has shipped the answer in 2–10 years.
